# 03 — Feature and Behavior Parity Ledger

Scope: every legacy route mapped to a native destination, compared across content/information hierarchy, navigation/return behavior, all controls/filters/sort/context actions/gestures, loading/empty/offline/error/retry/stale/success states, persistence/defaults, auth-dependent behavior, API mapping/pagination, VoiceOver semantics, and the "small-things ledger" (focus targets, remembered filters, scroll restoration, unread-becomes-read timing, save/follow announcements, timing, retry destinations, grammar, confirmation wording, toolbar order, pull-to-refresh semantics, auto-load-more thresholds/announcements).

This ledger is assembled from three parallel research slices covering all product domains: (3a) Home / Discover / For You / Search, (3b) Forums / Apps / Resources–Blogs–Bugs / Profile, (3c) Settings / Onboarding / Help–Academy / Submission wizards. Each slice used its own ID prefix (HOME-, DISC-, FY-, SEARCH- / FORUM-, APPS-, RES-, PROFILE- / SETTINGS-, ONBOARD-, HELP-, SUBMIT-).

Status vocabulary: PASS, PARTIAL, MISSING, REGRESSION, MANUAL VERIFY, INTENTIONALLY DEFERRED, NOT APPLICABLE, UNKNOWN / INSUFFICIENT EVIDENCE.
