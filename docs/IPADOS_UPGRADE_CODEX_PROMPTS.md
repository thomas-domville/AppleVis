# AppleVis iPadOS Upgrade — Ordered Codex Prompts

Run these in order. Each prompt assumes Codex has the repository root open. Require a build/test checkpoint before moving to the next prompt.

## Prompt 1 — Baseline and adaptive navigation foundation
Read `AGENTS.md`, `CODEX_IPADOS_UPGRADE_START_HERE.md`, `docs/IPADOS_UPGRADE_IMPLEMENTATION_SPEC.md`, and the iPadOS section of `docs/APPLEVIS_2026_1_MASTER_SPEC.md`. Inspect the current navigation architecture, especially `ContentView.swift`, `DiscoverView.swift`, and `AppNavigationStack.swift`. Implement only the smallest shared adaptive-navigation infrastructure needed for later master/detail screens. Do not convert feature screens yet. Preserve the three-tab architecture, `OpenAtFirstNewCommentAction`, existing deep-link behavior, and all current iPhone navigation. Do not introduce nested NavigationStacks. Prefer horizontal size class/window-adaptive behavior over device checks. Add targeted tests for any new state/selection logic. Build and run existing tests. Report exactly what changed, why, tests run, and any risks before stopping.

## Prompt 2 — Forums adaptive master/detail
Using the shared infrastructure from Prompt 1, convert Forums to adaptive navigation. Compact width must retain the current topic-list -> pushed `ForumTopicDetailView` experience. Wide/regular layouts should keep the forum/topic list visible while showing the selected topic in the detail column. Preserve filters, refresh, compose/report flows, deletion/unavailable-content handling, deep links, and `focusFirstNewCommentOnAppear`. Do not automatically steal VoiceOver focus into detail when a list selection changes. Preserve existing focus-restoration behavior and source-commented fixes. Ensure selection behaves sensibly across refresh/filter and width-class transitions. Add tests/UI tests where practical. Run localization audit only if user-facing strings change. Build/test and stop with a concise change/risk report.

## Prompt 3 — Apps adaptive master/detail
Convert App Directory list/detail workflows to adaptive navigation. Compact behavior must remain unchanged. In wide layouts, actual app lists and search results should be able to keep the list visible while showing selected `AppDetailView` in detail. Do not force an unhelpful split onto the initial category chooser. Preserve `AppPlatform` picker accessibility value/adjustable action, category loading/pagination/cache behavior, app removal callbacks, reviews/actions, edit/report flows, and first-new-comment behavior. Handle invalid selection after deletion/filtering. Avoid duplicate network fetches during resize. Add tests, build, and run relevant existing tests. Do not change unrelated screens.

## Prompt 4 — Discover hub adaptive grid and routing integration
Improve `DiscoverView` for iPad without changing the three-tab information architecture. Replace the fixed two-column hub grid with a genuinely adaptive layout that remains usable at large Dynamic Type sizes and across Stage Manager widths. Preserve search, Ask the Mouse, all current navigation destinations, `navigationPath` semantics, and the carefully documented VoiceOver focus behavior when switching back to the Discover tab. Integrate the Forums/Apps adaptive destinations cleanly without creating parallel routing paths. Test compact/wide transitions and search routing. Build/test before stopping.

## Prompt 5 — Podcasts adaptive list/detail
Add adaptive episode list/detail behavior for Podcasts. Compact navigation must remain the current stack experience. Wide layouts should use list/detail where it improves browsing. Playback state must survive layout changes without restart. Preserve all player keyboard controls, scrubber/playback-speed accessibility actions, downloads/queue behavior, and the existing mini-player overlay positioning fix in `ContentView.swift`. Do not rewrite the mini-player positioning unless a failing test demonstrates a need. Test full-screen portrait/landscape and narrow Stage Manager behavior. Add tests and build/test.

## Prompt 6 — Settings/Profile adaptive treatment
Audit Profile and Settings. Implement a wide Settings list/detail layout only if it can be done without nested NavigationStacks or dismissal regressions. Compact behavior must remain unchanged. Preserve Settings search, focus restoration, Done/dismiss semantics, and the separation between account/sign-in tools in Profile and configuration in Settings. If a safe split requires disproportionate architectural churn, choose a simpler adaptive-width Settings presentation and document why; correctness has priority over visual split view. Build/test and include regression checks for the navigation-unwinding problem documented in `SettingsView.swift` comments.

## Prompt 7 — iPad presentation, pointer, keyboard and resizing polish
Perform a focused iPadOS interaction audit across Home, Discover, For You, Forums, Apps, Podcasts, Profile and Settings. Check sheets versus popovers case-by-case; do not mechanically convert them. Audit custom cards/rows for pointer/trackpad affordance and ensure there is no touch-only action. Verify existing keyboard shortcuts and playback commands. Fix only concrete issues. Test Stage Manager and Split View transitions so layout responds to current available width, not hardware type. Check portrait/landscape and mini-player overlap. Keep changes small and documented.

## Prompt 8 — Accessibility certification and project completion
Run the full acceptance checklist in `docs/IPADOS_UPGRADE_ACCEPTANCE_CHECKLIST.md`. Prioritize VoiceOver: list/sidebar/detail traversal, no selection-triggered focus stealing, sensible focus after explicit navigation, collapse/expand behavior, sheets, filters, deletion, refresh and back. Test large Dynamic Type, Reduce Motion, Increase Contrast, Bold Text, Button Shapes, Reduce Transparency, Braille-friendly labels, and Switch Control reachability where possible. Run the full test suite and `tools/l10n_audit.py`. For visible/meaningful changes, update `WhatsNewView.swift`; check/update `HelpContent.swift`, `GuidedExperience.swift`, and `TipStore.swift` as required by `AGENTS.md`, including all supported localizations. Produce a final report mapping every acceptance-checklist item to pass/fail/not-testable and list any remaining manual device checks. Do not claim completion for untested items.

## Prompt 9 — Ask the Mouse first-class iPad experience and global shortcut
Treat Ask the Mouse as a first-class part of the adaptive iPadOS upgrade. First locate and understand every existing Ask the Mouse entry point/view/model and preserve them; do not create a duplicate flow. Add a global localized Command-M shortcut named “Ask the Mouse” that presents the existing experience safely from normal app contexts. Audit the Ask the Mouse UI at compact and wide iPad widths: question entry, suggestions/recent questions/history where present, generated answer, long-form reading width, links/resources, follow-up actions, save/share, and any memory controls. Preserve in-progress question/answer state across Stage Manager resizing. Ensure Full Keyboard Access and VoiceOver + hardware keyboard can complete the workflow. Do not force VoiceOver focus into a newly generated answer unexpectedly. Test large Dynamic Type and long answers. Update Help/Guided Experience/Tips/What’s New and all localizations as required by AGENTS.md. Build/test and report exact changes.

## Prompt 10 — Contact AppleVis global shortcut and keyboard command architecture
Add a global localized Command-Shift-C shortcut titled “Contact AppleVis” that opens the existing Contact AppleVis form without duplicating it. Preserve Command-C as standard Copy. Ensure presentation is safe from Home, Discover and For You and does not stack invalid modals or discard in-progress work. Then consolidate/audit the app’s explicit hardware keyboard commands: preserve Command-1/2/3, Command-R, Command-comma and existing podcast playback controls; add Command-F for current searchable contexts; add Command-N for New Topic only in appropriate forum contexts; add Command-Shift-S for Save/Unsave only where semantically clear and conflict-free. Prefer native Return/arrow/Escape behavior rather than unnecessary custom interception. Give every explicit command a localized discoverable title. Verify text entry retains normal editing shortcuts. Add focused tests where practical, run localization audit, build/test, and document any shortcut intentionally not implemented because of a system/accessibility conflict.

## Prompt 11 — Full Keyboard Access + VoiceOver keyboard certification
Perform a dedicated keyboard accessibility pass after all adaptive navigation work is complete. With Full Keyboard Access, verify that every major destination and action is reachable without touch across Home, Discover, For You, Forums, Apps, Podcasts, Profile/Settings, Ask the Mouse and Contact AppleVis. Test VoiceOver together with a hardware keyboard, paying special attention to split-view list/detail focus, Ask the Mouse question/answer navigation, Contact form fields, search, save actions and podcast playback. Keyboard focus and VoiceOver focus should be coherent but must not be forcibly synchronized. Verify shortcut discoverability titles, no collisions with text editing, no touch-only controls, and correct behavior at narrow/wide Stage Manager sizes. Update the acceptance checklist with pass/fail/not-testable evidence and fix concrete regressions before declaring completion.

# Adaptive Experience Expansion Prompts

These prompts supersede any instruction to stop after the iPad-only phases. Complete them after the existing prompts, while refactoring earlier work when necessary so the final architecture is shared rather than layered hacks.

## Prompt 12 — Convert the iPad plan into one adaptive iPhone/Duo/iPad architecture
Read AGENTS.md, the full implementation spec and acceptance checklist. Audit the codebase for `UIDevice`, `UIScreen.main`, orientation checks, fixed screen dimensions, custom safe-area assumptions and geometry-driven reloads. Refactor layout decisions to use SwiftUI size classes/local available space. Ensure the split-navigation infrastructure created in earlier prompts collapses/expands cleanly on iPhone Duo and narrow iPad windows. Do not create a separate Duo implementation. Build and run tests.

## Prompt 13 — iPhone Duo safe areas, poses and continuity
Using Xcode 27.1 and iPhone Duo Device Hub/simulator support, test all major screens across supported opened/closed/rotated/folded poses and Split View. Fix asymmetric safe-area/layout-margin issues, especially custom overlays, mini-player and Ask the Mouse composer. Preserve navigation selection, drafts/conversation where reasonable, and podcast playback through geometry changes. Add regression tests for pure logic. Document configurations tested.

## Prompt 14 — Typed routes, deep links and state restoration
Consolidate navigation into a typed routing layer without breaking existing deep links, first-new-comment behavior or tab semantics. Make the required major destinations routable. Add safe handling for stale/invalid routes. Add lightweight scene/navigation restoration for selected tab and meaningful selection where appropriate; do not persist sensitive authentication state. Add unit tests.

## Prompt 15 — App Intents, Siri, Shortcuts and Spotlight integration
Implement a focused App Intents layer reusing the typed router/business logic. Prioritize Ask the Mouse, Search AppleVis, Open Saved Items, Open Forums, podcast access and Contact AppleVis. Use localized accessible titles/dialogs. Respect authentication/privacy boundaries. Avoid duplicating UI navigation code inside intents. Add tests for intent-to-route mapping where possible.

## Prompt 16 — Full Keyboard Access, pointer, sharing and drag/drop review
Finish the approved keyboard command architecture, including Command-M, Command-Shift-C and contextual Command-F, while preserving system shortcuts and existing podcast commands. Verify discoverability and Full Keyboard Access across major workflows. Audit pointer/trackpad behavior and context menus. Standardize share-sheet support for appropriate content. Add drag/drop only where clearly useful and always retain an accessible non-drag path.

## Prompt 17 — Adaptive performance and automated regression coverage
Profile/audit resizing and size-class transitions. Prevent geometry changes from causing unnecessary network fetches, parsing or state reconstruction. Expand automated tests for routing, restoration, adaptive layout decisions, shortcuts and App Intents. Add stable UI tests for representative compact and regular navigation paths without making accessibility labels test-only or cryptic.

## Prompt 18 — Cross-device accessibility certification and release readiness
Run the final acceptance checklist across representative iPhone, iPhone Duo Device Hub poses/orientations/Split View, and iPad portrait/landscape/Split View/Stage Manager. Include VoiceOver, Full Keyboard Access, Dynamic Type, Reduce Motion, pointer/trackpad, light/dark and localization. Verify Ask the Mouse and podcast continuity. Prepare/document iPhone Duo App Store screenshot and product-page asset requirements and TestFlight matrix. Update project docs/What's New/Help/Guided Experience/Tips as AGENTS.md requires. Do not add Widgets or Live Activities. Produce a concise final report of tests, remaining limitations and files changed.
